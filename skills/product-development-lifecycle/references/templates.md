# 产品到开发模板集

按任务选用，不要求所有项目填写所有模板。空白表示未回答，不能默认等于“不适用”。

## A. 一页产品任务书

```markdown
# [产品/切片名称]

## 目标
- 用户：
- 场景：
- 要解决的问题：
- 预期变化：
- 成功指标或可观察结果：

## 证据与现状
- O 直接观察：
- R 外部资料：
- 当前产品/代码/数据：
- 尚未验证：

## 范围
- 必须包含：
- 明确排除：
- 优先级与可取舍项：
- 外部依赖和权限：

## 已确认决定
- D：

## 验收
- 用户操作：
- 应看到的结果：
- 必须覆盖的异常状态：
- 所需证据层级：
```

## B. 含糊与证据审计

| 原文/结论 | 可能含义 | 默认前提 | 当前证据 O/R/D/H | 相反解释 X | 成立的影响 | 不成立的影响 | 是否必须询问 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |

只向用户提出会改变下一产物的问题。问题中应包含当前理解、另一解释和两者影响。

## D. 技术方案映射表

| 需求/原型行为 | 模块责任 | 数据/接口 | 失败与恢复 | 测试与证据 | 风险/回退 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

补充架构边界、环境配置、权限、迁移、兼容、性能、监控和发布计划。每个用户行为都应找到实现位置和验收方式。

## H. 项目差异层

每个项目只保留相对于公共标准的差异：

```markdown
# 项目产品开发规则

- 公共知识库版本：
- 项目目标与生命周期当前阶段：
- 项目特有用户、平台和法规：
- 覆盖公共默认值的决定及原因：
- 当前阻塞与未验证项：
- 本项目证据和决策日志路径：
- 待提议回公共知识库的经验：
```

若没有明确覆盖条目，继续使用所固定版本的公共标准。项目差异不能直接修改公共知识库。
