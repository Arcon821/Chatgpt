# 知识库治理与跨项目同步

## 单一来源

`skills/product-development-lifecycle/` 是公共标准包。`SKILL.md` 负责AI路由，`references/` 是人与AI共同阅读的规则正文。项目文档只保存本项目差异、决策、证据和固定版本，不复制公共规则后自行修改。

公共知识库的目标是共享稳定判断方法，不收录每个项目的全部历史。具体代码路径、品牌色、业务字段、设备清单等通常属于项目层。

## 版本规则

使用语义版本：

- **major**：改变阶段门禁、角色权责、关键定义或不兼容的项目接入方式。
- **minor**：新增经过证据支持的工作模式、模板或适用领域，旧规则仍兼容。
- **patch**：纠错、澄清措辞、修复链接，不改变行为。

每个项目记录所采用的版本。公共版本更新不会自动推翻项目已经批准的需求或原型；项目先做影响检查，再决定升级。

## 经验升级流程

```text
项目发现 → 证据记录 → 通用规则提案 → 反例与边界
         → 用户审批 → 更新公共版本 → 通知相关项目复核
```

提案至少包含：观察证据、根因、拟议规则、适用和不适用条件、相反解释、采用/拒绝的双向影响、版本级别及需要复核的项目。

AI可以提出、整理和验证更新，只有用户确认后才升级公共标准。纯项目偏好留在项目差异层，除非多个项目证据表明它具有通用价值。

## 项目接入

相关项目应：

1. 安装或引用同一 `product-development-lifecycle` Skill 包。
2. 在项目入口文件中记录公共版本及项目差异文档路径。
3. 新任务先读取公共标准和项目差异，再读取当前需求和工程证据。
4. 项目结束把候选经验写入复盘，不直接改公共规则。

建议的项目入口：

```markdown
For product discovery, requirements, prototyping, delivery planning, or retrospective work, use the product-development-lifecycle skill version X.Y.Z. Read the project differences at [path]. Public standards are authoritative unless an approved project difference is listed.
```

## 同步策略

公开发布仓库 [`Arcon821/Chatgpt`](https://github.com/Arcon821/Chatgpt/tree/main/skills/product-development-lifecycle) 是公共版本的发布位置。项目可保留固定版本的本地副本，但应引用公开版本并记录差异；公共规则经用户批准后更新发布，再同步相关项目。

每次发布公共版本：

- 记录版本、日期、变更原因、证据和批准人。
- 列出受影响的阶段、模板和项目类型。
- 给相关项目发出“可升级/必须复核/不受影响”结论。
- 不在项目未审阅时自动改写项目需求、代码或原型。

相关项目升级时：

- 比较当前固定版本与目标版本。
- 检查项目差异是否与新规则冲突。
- 更新入口记录和受影响模板。
- 对正在进行的切片只应用安全且明确批准的变化；其余从下一切片开始。

## 变更记录

公共包保留 `CHANGELOG.md`，只记录对使用者有影响的变化。项目自己的复盘和决策日志仍留在项目中，通过知识提案引用，不复制到公共变更记录。

## 质量检查

发布公共版本前检查：

- 规则是否来自足够证据，而非单一偶发现象。
- 是否给出了反例和适用边界。
- 是否与其它规则冲突或重复。
- 人类读者与AI是否引用同一来源。
- 模板是否能产生可观察产物，而非只增加文档负担。
- Skill入口能否准确触发并按需读取参考文件。
- 相关链接、版本和项目接入说明是否有效。
